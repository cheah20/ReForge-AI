# Kiro Usage Log

| --- | --- | --- | --- |

| 2026-11-09 | Spec (requirements) | Wrote requirements.md for formbridge-pdf through requirements-first workflow | 16 numbered requirements covering PDF extraction, language registry, country packs, AI analysis, validation, PDF fill, accessibility, fixtures, and tests |
| 2026-11-09 | Spec (design) | Wrote design.md for formbridge-pdf with PBT prework tool | Produced full architecture, repo layout, API design, prompt design, model comparison plan, CJK prototype plan, batch size rationale, 12 correctness properties from prework analysis, and design tokens |
| 2026-11-10 | Hooks | Added three agent hooks: tests on save, a locale key check when `en.json` changes (it checks that keys are present, not that translations are good), and a commit guard | The first commit guard blocked every file write under the private notes folder, including Kiro's own progress notes. Kiro rewrote it to check only `git add` and `git commit`, with 7 unit tests for the guard |
| 2026-11-10 | Spec (tasks) | Ran formbridge-pdf tasks 1 to 9 in order, probing each fixture through the extractor | The probe found doubled field names (`clinic.clinic.branchCode`), radio widgets counted as separate fields and a pdf-lib lookup that threw at runtime. All three were fixed, and field counts now match the fixture spec: 22, 10, 14, 5 and 2 |
| 2026-11-10 | Property-based testing | Property 1 (no field silently dropped) ran fast-check over AI replies with omitted, unknown, duplicate and shuffled entries | Found a real bug on its second run: an AI reply with a whitespace-only label and question passed the schema and would have shown the user a blank question. The schema now rejects blank text and the analysis falls back to the PDF's own label. The shrunk case is kept as a regression test |
| 2026-11-10 | Hooks | The rewritten commit-guard hook fired on Kiro's own commit command | It blocked the commit because it read the shell redirection `2>&1` as a file path. Kiro fixed the guard to skip redirections and added a regression test |
| 2026-11-10 | Spec (review round) | Applied 18 review findings to the extraction code, each with a test that fails on the old code | Extraction now uses one shared field traversal for counting and evidence, never throws on malformed PDFs, and drops page text that touches a widget. 212 tests pass |
| 2026-11-10 | MCP (Context7) | First Context7 lookup: pdf.js 6.5.438 `getTextContent` options and `TextItem` fields, asked while debugging an empty page snippet | The docs did not say whether widget appearance text is extracted, so the privacy guard keeps excluding text near widgets. The docs also listed a `disableCombineTextItems` option, but it came from the `pdfjs-dist` master branch. The TypeScript check showed that the installed 6.5.438 does not have it, so Kiro removed it. While debugging, Kiro found that two fixture labels sat inside the 2pt privacy margin of a neighbouring field, and fixed their positions. Lesson: check MCP doc results against the installed version |
| 2026-11-10 | Hooks | Read the Kiro log to find why shell commands kept asking for approval | All 57 shell approval prompts so far came within 3 seconds of a hook run: the PreToolUse commit guard fired before every command. Kiro removed that hook and moved the same checks (private paths, secrets, non-Latin text) into a tracked git pre-commit hook, `scripts/git-hooks/pre-commit`, which `npm install` activates. The tests-on-save command hook is disabled for the unattended build, and the full suite runs at each checkpoint instead. Afterwards the log showed no hook runs and no hook-driven prompts. The prompts that remain come from the narrow shell allow list in the permission rules |
| 2026-11-10 | Steering | Added three public steering files: `privacy.md` (always on), `accessibility.md` (frontend files) and `testing.md` (test files) | `privacy.md` changed the output straight away. Its rule "do not promise more than the code does" showed that the upload notice said answers are never sent, while the translate route does send a description answer when the user asks. The review screen also used different wording. Kiro replaced both notices in all 7 locales with the wording from requirement 9.5 and added a test that the two screens match. The other two files have not changed any output yet: no frontend screen has been built since they were added |
| 2026-11-10 | Hooks | The `locale-sync` agent hook fired when `en.json` was saved during the notice change | Kiro ran the key check it asks for. Every core locale already had every key, because the new notices were translated in the same change |
| 2026-11-10 | Spec (Spike 1) | Ran the model comparison from design.md on real Workers AI with the real 22-field clinic evidence | The first run gave 0/6 valid replies: both models reason by default, and the reasoning used the whole 2,000-token budget before any JSON. A 2-field probe showed this, and the Context7 Workers AI docs gave the switch (`enable_thinking: false`). Rerun: Gemma 3/3 valid, 0 fields omitted, about 60 neurons per form (reported by Workers AI). Qwen at reasoning `low` was 0/3. Gemma was selected and the result recorded in design.md |
| 2026-11-10 | Spec (fixture cache) | Generated the precomputed AI cache for both acceptance fixtures in 6 core languages | All 6 clinic requests hit the 25 s timeout from the design, while the 14-field US form passed. Kiro raised the timeout to 45 s, with a test, above the 29 s spike maximum. The rerun wrote all 12 files, each first-attempt valid and complete. A test now checks that the Worker serves every file |
| 2026-11-10 | Hooks (git pre-commit) | The new git pre-commit hook ran on a real commit | It blocked the commit because Kiro had pasted the model's Chinese example questions into design.md, and the specs must stay English. Kiro rewrote that note in English and committed again |
