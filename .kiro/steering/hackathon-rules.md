# Kiroween 2026 Official Rules — always follow

Source: kiroween.devpost.com/rules (copied Nov 9, 2026).

## Hard requirements (breaking any = disqualification risk)

- **New project only**: everything must be built during the Submission Period (Oct 30 – Dec 4, 2026, 2:00 PM PT). Frameworks, libraries, and starter templates are OK, but **disclose any other pre-existing code** in the README.
- **Built with Kiro**: insufficient use of Kiro = disqualification. Use Kiro for real work, not just for show.
- **Category**: Frankenstein — stitch together seemingly incompatible technologies into one unexpectedly powerful app.
- **Functionality**: must install and run consistently, and work exactly as shown in the video and description.
- **GitHub** repo (not GitLab/Bitbucket), **public**, with all source code, assets, and setup instructions.
- **Open source license file** (MIT) that GitHub detects and shows in the repo's About section.
- **`/.kiro` at the repo root** with specs, hooks, and steering. **Never** add `/.kiro` or any sub-folder to `.gitignore`.
- **Working app URL** for judges (add test login + instructions in the Devpost form if needed). Must stay free and available until Jan 29, 2027.
- **Demo video**: under 3 minutes, public on **YouTube**, shows the app actually running, no copyrighted music or third-party trademarks without permission.
- **Everything in English** (or with English translation): description, video, testing instructions.
- **Third-party APIs/data**: only use them as their terms allow.
- Never commit secrets or personal data.

## Kiro write-up (judges read this — plan for it from day one)

Document how we used each feature, with concrete examples:

- Kiro IDE / CLI / Web / Crew — which ones and how they differed
- Custom agents
- Agent hooks — which workflows were automated
- Spec-driven development — how specs were structured, compared with vibe coding
- Steering docs — which strategy helped most
- MCP — what it enabled
- Property-based testing (PBT) — which requirements, what bugs it caught
- Kiro powers

Keep notes in `docs/kiro-usage-log.md` as we go.

## Judging (5 criteria, 20% each)

1. **Potential Impact** — real problem, real audience, useful and accessible.
2. **Technological Implementation** — deep, varied, thoughtful use of Kiro; experimentation.
3. **Design** — complete, polished product experience, not a proof of concept.
4. **Innovation/Idea** — novel concept, unusual combination of technologies.
5. **Presentation** — video shows the app end to end; clear problem, audience, and why it matters.

## Bonus prizes we can target

- **Best Demo** — top Presentation score within the top 10% overall.
- **Bonus Blog** — public blog post about Kiro + this project during the Submission Period; must say it is written for the Kiroween 2026 hackathon.
- **Social Blitz** — public post that **starts with** `#KiroweenHackathon26`, sharing a favorite thing about Kiro and how it changed the way we build. Post during the Submission Period.
- **Best Student Project** — only if the entrant is currently a student (needs LinkedIn, student email, year, degree, school).
